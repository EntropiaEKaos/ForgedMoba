# ForgedMoba — Technical Audit Baseline

Date: 2026-09-22
Audited baseline: main @ 9afa67738ab9e5217fac73d19917086d63f32923

## Executive summary

ForgedMoba already contains a meaningful playable offline MOBA prototype: heroes, items, bots, lanes, jungle, objectives, fog/wards, draft, skins, runes, VFX, HUD and local persistence. The primary engineering risk is not missing content; it is that simulation, input, AI, rendering, VFX and local networking are concentrated in the legacy Game class.

The production direction is therefore an incremental extraction, not a rewrite. The existing client remains playable while authoritative systems migrate to a deterministic headless simulation core.

## Verified baseline findings

- src/game/engine.ts is approximately 5k lines and owns simulation + rendering + input + AI.
- src/App.tsx is a large UI/HUD surface and should be decomposed later, after the simulation boundary is stable.
- The legacy simulation uses variable frame delta and Math.random(), so it is not suitable as an authoritative deterministic core.
- Legacy projectiles/buffs contain object/function references, making complete game state difficult to serialize for replay/reconnect/server snapshots.
- Matchmaking created IDs but did not place sockets in Socket.IO rooms.
- Client matchmaking listeners were registered on every queue join and were not removed.
- JWT tokens were signed but not verified by the Socket.IO server.
- Development passwords were stored directly in memory without hashing.
- Client-supplied game:state was relayed, which is incompatible with an authoritative anti-cheat model.
- Admin content is local-browser state today; online matches will eventually require a server-owned content version/hash.
- No repository CI workflow or deterministic simulation tests existed at baseline.
- Documentation counts for heroes/items were inconsistent with code and should no longer be treated as certification evidence.

## Foundation decisions

1. Preserve the legacy engine until migrated behavior has equivalent tests.
2. New authoritative simulation code lives under src/simulation/.
3. New cross-client/server contracts live under src/shared/.
4. Simulation uses fixed integer ticks (30 Hz target), seeded RNG and entity IDs.
5. Simulation must not import DOM, React, Canvas, WebAudio, localStorage or legacy game modules.
6. Clients send commands/intents. Clients never author authoritative damage, gold, kills or world state.
7. CI must reject simulation boundary violations and deterministic divergence.
8. Full rollback is not the default networking strategy. Target architecture is authoritative server + client prediction + reconciliation + interpolation.

## Migration safety rule

No system is removed from src/game/engine.ts until:

- the new simulation behavior exists,
- deterministic tests cover it,
- a compatibility adapter exists where needed,
- browser behavior is verified,
- CI is green.

This is the primary guard against losing working gameplay during the migration.
