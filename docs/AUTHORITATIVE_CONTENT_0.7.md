# Authoritative Content 0.7

## Goal

ForgedMoba now separates **editable prototype drafts** from **published online authority**.

The browser Admin panel can still edit the rich legacy/offline catalog for rapid iteration. Online matches do not trust those browser-local values. Instead, they execute a validated published pack whose deterministic hash is part of every match identity.

## Publish model

```text
draft data
  ↓
schema validation
  ↓
canonical JSON
  ↓
deterministic hash
  ↓
immutable published pack
  ↓
server + compatible client
  ↓
authoritative match
```

The current published identity is generated by `src/shared/authoritativeContent.ts` and has the form:

`authority-0.7.0+<hash>`

Changing a gameplay-relevant field changes the hash.

## Current authoritative catalog

The first pack intentionally contains only gameplay already implemented by the deterministic online core:

- Gareth
- Luxana
- their authoritative Q runtimes
- Espada Longa
- Cristal de Rubi
- Botas de Velocidade
- Picareta

This is safer than pretending the full legacy 23-hero / 39-item catalog is online-authoritative before those mechanics have deterministic server runtimes.

## Runtime values moved into content

Hero creation now reads from the published pack:

- max HP
- attack damage
- attack range
- attack cooldown
- movement per simulation tick
- crit chance

Q runtime reads:

- runtime kind
- range
- base damage
- AD ratio in permille
- cooldown ticks
- status kind/duration/magnitude
- line width where applicable

Economy reads:

- starting gold
- max inventory slots
- shop radius
- item cost
- supported item stat deltas
- hero respawn / kill reward rules

## Authoritative purchases

`buy` is now a simulation command.

The server accepts a purchase only when:

- the item exists in the published pack;
- the hero is alive;
- the hero is inside the authoritative shop radius around spawn;
- inventory has capacity;
- the hero has sufficient authoritative gold.

The server subtracts gold, adds the item ID to serializable inventory state and applies the published stat delta. Client prediction runs the exact same simulation function and later reconciles from the server acknowledgement.

## Content compatibility gate

The compiled client advertises its local content version in:

- Socket.IO auth;
- matchmaking join requests.

The server rejects mismatched versions before a player can enter an authoritative queue. Every snapshot still carries `contentVersion`, and the client refuses mismatched snapshots.

The current published pack is exposed read-only at:

`GET /api/content/current`

## Admin boundary

The existing Admin panel is deliberately **not** allowed to publish browser `localStorage` directly into multiplayer authority.

A new Published tab shows the exact online version/hash/catalog and explains the pipeline. Local hero/item edits remain drafts until a future authenticated, role-protected, persistent publishing API is introduced.

This avoids turning the browser Admin workflow into a cheat surface.
